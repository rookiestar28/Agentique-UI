# Runtime Foundation Acceptance

Disposition: `repository-side-accepted-local-only` for the tested Windows fixed Python lane.

## Accepted Repository Capabilities

- Canonical exact-address run events with contiguous ordering and one terminal.
- Native-owned explicit consent before fixed-lane start.
- Asynchronous exact-handle coordination with cancellation and late-result fencing.
- Durable product projection committed before terminal publication.
- Bounded immutable working-set checkpoints committed before product projection.
- Offline digest-pinned evaluation with fixed adapters, deterministic checks, independent human
  review, and cleanup-failure enforcement.

The aggregate manifest pins all seven predecessor evidence rows, eight public contract versions,
the no-package-adoption disposition, lifecycle ordering, migrations, reverse-order rollback,
negative capability posture, downstream residuals, and the exact validation candidate. Any missing,
unknown, duplicated, widened, or stale field makes the disposition `pending`.

## Explicit Non-Claims

This acceptance does not establish a cross-platform packaged desktop, signed installer, updater,
hosted runtime, universal agent execution, generic shell/process access, arbitrary filesystem or
network authority, automatic downloaded execution, side-effect replay, or production runtime.
macOS/Linux native supervision and product E2E, signed package/notarization/update evidence, hosted
CI, provider, deployment, and live production proof remain separate gates.

Shared foundation evidence is counted once. Downstream command transition, live revocation,
run-folder product journey, process-tree recovery, durable registry, true runner E2E, public claims,
and checkpoint time-travel residuals remain open rather than being inferred from source presence.
